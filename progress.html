Findings so far

Redesign: the stats strip read out of order on a phone The app is now always dark with a near-white accent, since a saturated accent competed with the surprisal wash for the reader's attention and the two mean unrelated things. The one defect the redesign introduced was caught by the 375px capture: collapsing the four readouts to two columns by grid auto-flow filled each column top to bottom, so the strip read across as 1, 3, 2, 4 while the markup said 1, 2, 3, 4, and the rule meant to divide the columns landed inside one of them. Fixed with explicit cells.
Wave 3 FAIL: the prompt box was lying The Prompt field was an editable textarea that replay mode silently ignored: type a new prompt, press Run, and the old fixture streamed back under correct arithmetic describing a prompt no longer on screen. Its only caption reassured the reader the prompt was handled locally, when the truth was that it was discarded. Now read-only in replay, and it says why.
Cold start passed 11/11, and still found two bugs A fresh agent ran the finished build from the README alone with no API key: install, stream, both sliders, fork by mouse, fork by keyboard, branch switching, tests, gate self-test. It also found that Enter on a token dead-ended the keyboard route, and that a run which ended early pinned every later setting to that token count, truncating text mid-word. Both fixed and re-measured.
Wave 2 FAIL: the sliders did not do what the app said Moving a slider never re-sampled committed tokens, while the copy asserted it did. A committed token could be drawn as both chosen and excluded, at a probability the same panel printed as zero, under a temperature of 0 the help text called deterministic. The engine now re-derives the whole completion whenever settings change — affordable because the randomness is keyed by position, and measured at no frame cost at all (p95 unchanged at 6.20ms).
Cold start: the fork was mouse-only A fresh agent passed all nine checklist items from the README alone, then noted that completion tokens were bare spans with no role or tabindex — so selecting a token, the first half of the headline interaction, was unreachable by keyboard. It is now a listbox with a roving tabindex, verified forking end to end from the keyboard.
Wave 0 FAIL: the panel did not reconcile Bars summed to 144% once top-p bit, because survivors were drawn renormalised while discarded candidates kept their pre-cut length. The tail was counted twice, and CHOSEN P was frozen at 95.8% beside a committed-token bar drawn at 55.5%. Fixed with two explicit bar layers, coverage stated once, and a live chosen-p.
Wave 1 FAIL: the rule was never drawn Top-p is a rule about a running total and no running total appeared anywhere, so the hairline between two rows was an assertion the reader had to verify by mental arithmetic. There is now a Σp column on the same basis as the p column beside it, and the caption names the rank where it crosses the threshold.
The surprisal tint encoded nothing Measured, not assumed: 63 of 68 tokens in the default fixture fell in the first bucket, which is transparent with a zero-width underline. Thresholds were taken from the range surprisal can span rather than the range it occupies. Rebased on probability landmarks; occupancy went from 93/0/1/6/0 to 69/24/0/0/7.
Idle pages cannot be frame-measured Chromium skips compositor frames when nothing changes. Measured: an idle page delivered ~585ms of frames across a 2000ms window, and the percentiles of that starved burst looked excellent. The probe now reports the span it covers and the judge returns INSUFFICIENT_DATA rather than a green tick.
Self-test must match the real configuration Frame timing originally ran headless in the self-test while the real gate runs headed. Validating a setup the real run never uses proves nothing.
White on the accent fails in dark theme Measured at 2.64:1, not assumed. The dark theme uses dark ink on the accent fill instead. Worst text contrast across both themes is 5.27:1.
Live mode ships untested No OPENAI_API_KEY in this environment, so it cannot be smoke-tested. It is built, unit-tested at the parser level, and kept behind the replay default. The README says so plainly.
